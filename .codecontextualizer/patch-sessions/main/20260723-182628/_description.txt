Intención:
Eliminar el bloque `<style>` del template de `SecureDemoPage` para evitar que el motor procese CSS con `CssScoper` (que utiliza `ph-css`), el cual está causando que JaCoCo lance una excepción de instrumentación y rompa el build de los tests HTTP.

Alcance:
- Modifica únicamente el método `template()` en `SecureDemoPage.java`.
- No altera `onInit`, `addItem`, ni la lógica de estado.
- No aborda el problema raíz de JaCoCo con `ph-css` en otros módulos, pero evita que esta página dispare el fallo durante tests de integración HTTP.

Motivo:
Al incluir un bloque `<style>`, la página obliga al runtime a invocar `CssScoper.scope()`. Esto carga la clase `ParserCSS30TokenManager` de la librería `ph-css`, la cual es demasiado grande para JaCoCo 0.8.12 y lanza `MethodTooLargeException`. Si se elimina el CSS de esta página, se evita pasar por el escoper para este componente, permitiendo que el build avanze sin enroscar a JaCoCo (que ya fallaba en pruebas previas en `CssScoperTest` y posiblemente en `JrxHttpApiTest`).

Validación manual sugerida desde el punto de vista del usuario:
- Verificar que el módulo demo compila correctamente y que la página `/secure-demo` renderiza el estado, la tabla y el formulario (aunque sin estilos CSS).
- Confirmar en los logs que el error `MethodTooLargeException` desaparece durante el scaneo o testeo de `SecureDemoPage`.
