Intención: Cambiar la configuración de JaCoCo de `excludes` a `includes` para que el agente solo instrumente las clases del proyecto (com/ciro/**), evitando que intente leer y procesar bytecode de librerías de terceros (ph-css) que contienen métodos demasiado grandes para ASM/JaCoCo.

Alcance: Se modifica únicamente la configuración del bloque `<configuration>` del plugin jacoco-maven-plugin en pom.xml (raíz), reemplazando `<excludes>` por `<includes>`.

Motivo: La exclusión anterior (excludes=com/helger/**) se pasó correctamente al agente, pero JaCoCo aún necesita leer el bytecode de TODAS las clases cargadas para decidir si las excluye. Al leer ParserCSS30TokenManager, ASM lanza MethodTooLargeException antes de que la exclusión aplique. Con `includes=com/ciro/**`, el agente ignora desde el principio cualquier clase que no coincida con el patrón, sin siquiera leer su bytecode.

Validación manual sugerida desde el punto de vista del usuario:
- Ejecutar mvn clean install desde la raíz del proyecto.
- El argLine debe mostrar includes=com/ciro/** en lugar de excludes=com/helger/**.
- El build debe completar sin errores de JaCoCo MethodTooLargeException ni IllegalClassFormatException.
