Intención:
Crear un ejemplo runnable de @Authorize en jreactive-demo-spring con infraestructura mínima de autenticación por sesión, un AuthorizationProvider concreto registrado vía @PostConstruct, endpoints REST de login/logout y una página demo protegida enlazada desde el Hub.

Alcance:
- Se crean 3 archivos nuevos en jreactive-demo-spring:
 * com/ciro/jreactive/DemoSecurity.java (consolida DemoPrincipal, DemoAuthFilter, DemoAuthorizationProvider y @Configuration con @PostConstruct)
 * com/ciro/jreactive/DemoAuthController.java (REST: /demo/login, /demo/logout, /demo/me)
 * com/ciro/jreactive/SecurePage.java (página @Stateless con @Authorize a nivel clase y método)
- Se modifica HomePage.java para añadir un enlace a /secure.
- No se toca archivos del framework.

Motivo:
La anotación @Authorize y el SPI AuthorizationProvider no tenían un ejemplo runnable ni provider concreto en el demo. Este parche aporta el eslabón mínimo: identidad ficticia por sesión + provider que extrae roles del Principal + página demo con métodos protegidos.

Validación manual sugerida desde el punto de vista del usuario:
- fetch('/demo/login', {method:'POST', headers:{'Content-Type':'application/json'}, body: JSON.stringify({user:'admin', roles:['ADMIN']})})
- Navegar a /secure, pulsar "Revelar Secreto" (ADMIN): debe funcionar
- fetch('/demo/logout', {method:'POST'}), refrescar /secure, pulsar botones: debe devolver FORBIDDEN
