Descripción:
Intención:
Impedir que valores controlados por la aplicación cierren las etiquetas script utilizadas para inicializar JReactive y ejecuten JavaScript inyectado.

Alcance:
Se hace segura la inserción de los parámetros URL, el estado @Stateless y el identificador raíz dentro de scripts HTML. Se añade una prueba de regresión con payloads que contienen cierres de script. No se modifica el formato criptográfico de JrxStateToken, la hidratación, el transporte, el escape del contenido HTML ni las APIs públicas.

Motivo:
JrxHttpApi inserta actualmente JSON crudo y un identificador entre comillas simples dentro de etiquetas script. JSON válido puede contener la secuencia </script>, que el parser HTML interpreta como el cierre real de la etiqueta y permite crear un segundo script. No bastaba reutilizar el escape HTML porque los valores deben seguir siendo JavaScript/JSON válidos; se necesita neutralizar los caracteres sensibles mediante escapes Unicode.

Validación manual sugerida desde el punto de vista del usuario:

* Crear una página @Stateless cuyo estado contenga </script><script>alert('xss')</script>.
* Abrir la página e inspeccionar el HTML generado.
* Confirmar que aparecen secuencias como \u003C/script\u003E y que no se crea ni ejecuta una segunda etiqueta script.
* Confirmar que el valor original se hidrata correctamente en el estado del navegador.
* Ejecutar mvn -pl jreactive-runtime-jvm test -Dtest=JrxHttpApiTest.
* Ejecutar finalmente mvn test desde el proyecto padre.
